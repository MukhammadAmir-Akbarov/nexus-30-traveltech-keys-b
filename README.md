# NEXUS30 · Трек TravelTech · «Надёжный спутник туриста»

**Живой прототип:** https://turizm-hamroh.onrender.com
*(бесплатный тариф засыпает после 15 минут тишины — первый запрос может занять до минуты)*

Три функции кейса B в одном контексте поездки: **проверка фактов** по корпусу
источников (текстом, голосом и фотографией), **персональный маршрут** с погодой,
транспортом и бюджетом, и **подбор гида**, чья репутация складывается из тех же
проверок — по каждому объекту отдельно.

```
keys-b/          приложение (Next.js) — README внутри: требования кейса ↔ реализация
keys-b/DEMO.md   сценарий показа с рабочими примерами
WORK.md          инженерный журнал: что и почему решалось
```

**Быстрая проверка качества** — то же, что запускаем сами:

```bash
cd keys-b && npm ci
npm run check        # самопроверка логики: поиск, планировщик, репутация, переводы
npm run build && npx next start -p 3000 &
BASE=http://127.0.0.1:3000 npm run e2e   # сквозной прогон против живого сервера
```

Документация привязана к коду тестом: число абзацев корпуса и число проверок
в README сверяются с фактическими — расхождение роняет `npm run check`.

## Что выбрано и почему

**Работаем над кейсом B.** Кейс A целиком входит в B: trip-planner — это второй из трёх
модулей кейса B. Взяв A, команда делает ровно то же, что команды с кейсом B, но без двух
дифференцирующих функций. При этом trip-planner — самая частая идея хакатонов, и по
критериям «соответствие проблеме» (30%) и «инновационность» (15%) он один не выигрывает.

| | Кейс A | Кейс B |
|---|---|---|
| Партнёр | Yandex | Комитет по туризму |
| Объём | 1 функция | 3 связанные функции |
| Зависимость от партнёрских API | карты/погода — `[ANIQLANADI]` в ТЗ | база объектов/гидов — тоже под вопросом |
| Дифференциация | низкая | высокая (проверка фактов ни у кого не будет) |
| Пересечение | — | включает в себя весь кейс A |

Риск кейса B — зависимость от данных партнёра — закрыт тем, что прототип работает на
собственном демо-датасете и не ждёт ничего снаружи.

## Где кейс A

Кейс A («SafarAI») сделан форком этого прототипа и живёт в отдельном репозитории —
здесь папка `keys-a/` намеренно в `.gitignore`, чтобы два кейса не мешали друг другу
в истории.

# TurizmHamroh — надёжный спутник туриста

**NEXUS30 · трек TravelTech · кейс B «Надёжный и персонализированный спутник туриста»**
Партнёр кейса — Комитет по туризму Республики Узбекистан.

**Живой прототип:** https://turizm-hamroh.onrender.com
*(бесплатный тариф засыпает после 15 минут тишины — первый запрос может занять до минуты)*

---

## Идея в одном абзаце

Турист не может проверить то, что ему рассказывает гид. Мы перевернули задачу:
приложение рассказывает туристу об объекте **до того, как гид открыл рот** —
по координатам, с фактами из проверяемых источников. Проверка слов гида
становится естественным продолжением: каждый вердикт записывается в репутацию
гида **по конкретному объекту**, и подбор гида опирается на эту репутацию,
а не на нарисованные звёзды. Три функции кейса — проверка фактов, маршрут,
подбор гида — работают на одном контексте поездки и питают друг друга данными.

## Попробовать за 90 секунд

1. **«Я на месте»** — `/nearby`, кнопка «Регистан»: брифинг из фактов
   с источниками, что смотреть внутри, время осмотра. Координата в демо
   подставляется кнопкой и помечена; сам расчёт (радиус 500 м, ближайший
   объект, сборка брифинга) — настоящий.
2. **Проверка** — `/check`, фраза «Registon XII asrda qurilgan» (или то же
   по-русски/по-английски): **опровергнуто**, с верной датировкой и ссылкой
   на ЮНЕСКО. Работает текстом, голосом и фотографией.
3. **Репутация** — выберите в проверке гида: вердикт зачтётся ему по объекту
   «Регистан», и в `/guides` его точность по этому объекту изменится.
4. **Маршрут** — `/plan`: дни с погодой, часами осмотра, дорогами и бюджетом.

## Архитектура доверия — четыре принципа

**1. Слой правил никогда не подтверждает — только опровергает.**
Совпавший год не доказывает остальную часть фразы, поэтому «подтверждено»
из правил не выдаётся в принципе. Ловим то, что умеем ловить надёжно:
перепутанный век и год, на трёх языках. Спорная тема не считается ошибкой
гида — показываются позиции сторон с источниками (`keys-b/src/lib/verdict.ts`,
`disputed.ts`).

**2. Репутация гида — измеренная, по каждому объекту, с правом на возражение.**
Ранжируем по нижней границе Вильсона, а не по голой доле: новичок с одной
удачной проверкой не обгонит гида с двадцатью. Точность по объектам маршрута
весит больше общей: «хороший гид вообще» и «хороший гид именно на Регистане» —
разные вещи. Гид видит вердикты о себе и может возразить (`/guide`);
несуществующему гиду вердикт не записывается (`keys-b/src/lib/match.ts`, `store.ts`).

**3. Каждая цифра — из данных, и это охраняется тестом.**
Число фактов на странице «Как это работает» берётся из корпуса; число абзацев
и число проверок в документации сверяются с фактическими при каждом
`npm run check` — расхождение роняет сборку. Документ, который не может врать.

**4. Честность видна на экране.**
Синтетические гиды, демо-координата, режим «без модели, по правилам»,
демо-точки инфраструктуры — всё помечено там, где показывается. Прототип,
который знает свои границы, убедительнее прототипа, который делает вид.

## AI в продукте

Модель подключается строкой `provider/model` через AI Gateway
(`AI_GATEWAY_API_KEY`) и **опциональна**: без ключа работает слой правил
и предзаписанные ответы, интерфейс честно показывает режим. Принцип один
во всех модельных местах: **модель объясняет, но не решает** — вердикт
выносят правила и источники, маршрут собирает планировщик, распознанная
фотография сверяется с закрытым списком объектов. Включение ключа улучшает
язык ответов, не меняя логику доверия.

## Качество — проверяется одной последовательностью

```bash
cd keys-b && npm ci
npm run check                     # самопроверка: поиск (uz/ru/en), планировщик,
                                  # репутация, переводы, согласованность документации
npm run build && npx next start -p 3000 &
BASE=http://127.0.0.1:3000 npm run e2e    # 41 проверка против живого сервера
```

TypeScript строгий, ESLint чистый, сборка — 59 страниц. В журнале `WORK.md` —
инженерные решения с причинами: почему MapLibre вместо Leaflet, почему поиск
без эмбеддингов, как чинился белый экран воркера карт.

## Данные и приватность

Геолокация обрабатывается в браузере — координаты **не отправляются на сервер**
(это свойство кода, видно во вкладке Network). Профилей туристов нет: проверки
привязаны к обезличенному идентификатору устройства. Синтетические данные гидов
не содержат сведений о реальных людях — по требованию организаторов. Фотографии
и данные OSM используются по свободным лицензиям с атрибуцией (`/how`).

# Что осталось сделать руками

Три вещи упираются в доступы, которых у меня нет: дашборд Render, права на
репозиторий и ключ модели. Здесь — точные шаги, чтобы каждая заняла минуту.

---

## 1. Постоянный адрес вместо туннеля

Quick-туннель `cloudflared` живёт часами и умирает молча — за эту неделю он
падал дважды, оба раза перед показом. На защите это лотерея.

1. Render → **New → Blueprint**.
2. Выбрать репозиторий `nexus-30-traveltech-keys-b`, ветку **elbek**.
   На 16 августа деплой идёт с неё: `cyber` и `elbek` разошлись, а публичный
   адрес нужен раньше, чем закончится слияние. Причина записана в `render.yaml`.
3. Render прочитает `render.yaml` в корне репозитория (не в `traveltech/` —
   такой папки нет) и покажет один сервис `turizm-hamroh`. Нажать **Apply**.

Что произойдёт само, без ручной настройки:

| Переменная | Откуда возьмётся |
|---|---|
| `SESSION_SECRET` | Render сгенерирует случайное значение |
| `ADMIN_PASSWORD` | Render сгенерирует случайное значение |
| `ADMIN_EMAIL` | `admin@nexus30.uz` из блюпринта |
| `NODE_VERSION` | 22 |

**Пароль администратора смотреть здесь:** сервис → *Environment* → `ADMIN_PASSWORD`.
На странице входа он не показывается — подсказка появляется только тогда, когда
пароль действительно демонстрационный.

> Почему это важно именно так: раньше блюпринт не задавал `SESSION_SECRET` и
> `ADMIN_PASSWORD`. На постоянном адресе это значило бы предсказуемую подпись
> сессии и пароль `nexus30`, который приложение само же и печатало на странице
> входа. То есть администратором становился любой, кто открыл ссылку.

Free-план засыпает после 15 минут простоя — первый запрос после паузы идёт
30–50 секунд. Перед выходом на сцену открыть адрес заранее и не закрывать.

## 2. Напарники в репозиторий

Мне нужны их логины на GitHub (не почты) — без них API отдаёт 403.

Когда пришлёшь, добавляю одной командой:

```bash
gh api -X PUT repos/MukhammadAmir-Akbarov/nexus-30-traveltech-keys-b/collaborators/ЛОГИН \
  -f permission=push
```

Либо сам: репозиторий → *Settings* → *Collaborators* → **Add people**.

Договорённость по веткам прежняя: `cyber` — твоя, `dev` — напарника,
в `main` сливаем через pull request перед сдачей.

## 3. Ключ модели

Без ключа приложение работает целиком — на правилах и предзаписанных ответах,
и режим честно подписан в интерфейсе. Ключ включает ветку модели: маршрут и
формулировки вердиктов начинает писать она, правила остаются запасным путём.

Локально:

```bash
cd keys-b
# .env.example в репозитории нет — создать .env.local вручную:
echo 'AI_GATEWAY_API_KEY=...' > .env.local
# необязательно: AI_MODEL=... — по умолчанию anthropic/claude-sonnet-5 (src/lib/model.ts:3)
npm run build && npx next start -p 3000
```

На Render: сервис → *Environment* → `AI_GATEWAY_API_KEY` → вставить значение →
*Save*, сервис переедет сам.

Модель задаётся строкой `provider/model`, по умолчанию `anthropic/claude-sonnet-5`
(`src/lib/model.ts`). Сменить — переменной `AI_MODEL`, пересборка не нужна.

**Проверить, что ключ подхватился:** на `/plan` метка рядом с «Итого» должна
смениться с «без модели, по правилам» на «составлено моделью». Если не сменилась —
ключ не виден процессу, а не сломался маршрут.

## Перед выходом на сцену

```bash
cd keys-b
npm run check              # логика: планировщик, погода, намаз, репутация
npx next start -p 3000 &
BASE=http://127.0.0.1:3000 npm run e2e   # 30 проверок против живого сервера
# BASE обязателен и именно по IPv4: с `localhost` fetch в Node 22 сначала идёт
# на ::1, сервер слушает IPv4, и все 30 проверок падают с «fetch failed».
```

Оба должны быть зелёными. `npm run e2e` умеет работать и против публичного
адреса — тогда проверяется ровно то, что увидит жюри:

```bash
BASE=https://адрес-сервиса.onrender.com npm run e2e
```

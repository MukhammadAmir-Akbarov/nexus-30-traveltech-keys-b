# Кейс A · Yandex · «Персонализированный AI-маршрут»

Запасной вариант трека. Кода здесь нет намеренно: кейс A целиком покрывается
модулем «Маршрут» из [../keys-b](../keys-b). Эта папка нужна, чтобы требования
кейса A были зафиксированы и переключение заняло часы, а не сутки.

## Требования кейса (из официального сборника NEXUS30)

| № | Требование | Где уже реализовано в keys-b |
|---|---|---|
| 1 | Персонализация под тип поездки и пожелания | `src/lib/planner.ts` → `scorePlace()`, контекст `TripProvider` |
| 2 | Учёт погоды | **не сделано** — см. ниже |
| 3 | AI формирует цельный маршрут, а не список | `src/app/api/plan/route.ts` (structured output) |
| 4 | Визуализация маршрута и последовательности | `src/components/RouteMap.tsx` (Leaflet + нумерация + линия) |
| 5 | Сценарии соло / семья / группа | `travelType` в контексте, влияет на отбор объектов |

## Что нужно доделать, если переключаемся на A

Полный план работы — в **[PLAN.md](PLAN.md)**: архитектура форка, модуль погоды,
сравнение соло/семья/группа, самопроверка, демо-сценарий, риски и чек-лист готовности.

Коротко: единственный настоящий разрыв — **погода** (§6.2 ТЗ). Остальное либо уже
есть в keys-b, либо является перестановкой существующего.

Объём: 14–18 человеко-часов, при трёх исполнителях — 6–8 часов календарного времени.

## Почему сейчас не он

Кейс A — подмножество кейса B и самая ожидаемая идея на треке. Обоснование выбора —
в [../README.md](../README.md).
